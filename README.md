# 大老二 Big Two｜好友連線版

正式獨立 Repository： https://github.com/YiQ1796/BigTwo_Web

本專案**不與財富帝國共用遊戲原始碼或網站**。第一版支援四個座位、真人不足 AI 自動補位、六碼房間、PeerJS/WebRTC 房主連線、單張／對子／三條／順子／葫蘆／鐵支／同花順，第一局必須由梅花 3 開始，13 張一條龍可直接獲勝。

## 遊戲網址與部署
預定 GitHub Pages 網址： https://yiq1796.github.io/BigTwo_Web/ （需以 Pages Action 成功與公開頁面實際載入為準）。

部署工作流程：.github/workflows/pages.yml。GitHub Pages 第一次啟用若尚未設定，Settings → Pages → Build and deployment → Source 選擇 GitHub Actions。

## 撲克牌圖片
目前是暫用 CSS／文字牌面；以後使用者提供圖片時，放入 docs/assets/cards/，在 docs/card-assets.js 設定 window.BIG_TWO_CARD_IMAGES 映射，新圖直接取代舊牌面，禁止疊加。詳見 CARD_ASSET_SPEC.md。

## 技術限制與測試
此版本使用第三方公開 PeerJS signaling 和瀏覽器 P2P，部分 NAT / 公司網路可能需要 TURN 服務才能互連。房主須保持網頁開啟；房主關閉、重新整理及玩家跨網路互連必須用真實裝置驗收，不可只憑網站載入判定多人連線已通過。

## Code Review 後續改善
1. PeerJS 斷線重連及房主重新整理後同房號恢復應加入定時重試與狀態版本核對。
2. 客戶端訊息應加入限流、回合版本與重放請求防護，避免短時間重複操作。
3. AI 的合法牌型評估應加入拆牌代價、對手剩餘張數與策略評分，並擴充單元測試。

## V0.5.2｜正式牌型與 AI 出牌策略（2026-10-30）
- 允許出牌張數為 **1、2、5**。三張同點數不能單獨出；葫蘆必須為 **三條 + 一對**（五張）。
- 對子為同數字兩張；鐵支為四張同數字 + 一張不同數字；順子為五張相鄰點數、花色不限；同花順為五張相鄰點數且同花色。沿用既定 2>A>...>3 與 ♠>♥>♦>♣。
- AI 策略獨立在 `docs/ai-strategy.js`，自由出牌偏好低牌、避免拆牌、保留 A/2 控制；壓牌時先比可用最小牌、依對手剩餘張數決定是否節省大牌；能一次出完優先獲勝。
- 不讀取其他玩家暗牌，只使用房主驗證出的合法候選與各玩家公開剩牌張數。
- 加入規則與 AI 回歸測試，Pages 部署前需通過測試。原 V0.5.1 回退分支：`safe-rollback-v051-before-rules-ai-20261030`。

## V0.5.5｜手機 WebRTC 協商失敗、自動恢復與房主訊號處理（2026-10-31）
- 修復加入房間時還未收到房主狀態就顯示空牌桌的錯誤：必須真正收到主機的 `state` 訊息後才進入遊戲畫面。
- `negotiation-failed`、房主失聯、連線逾時、訊號中斷、手機回到前景／網路恢復，均加入可控的重新連線流程：新建 Guest Peer 和 DataConnection、14 秒等待、階段性延遲、最多 6 次自動嘗試與手動「重新連線」。嘗試與連線世代 ID 隔離，舊連線的 close 事件不得破壞新連線。
- 一旦重新取得狀態，使用原本玩家 token 恢復同一座位；重連期間禁止出牌／PASS，避免在失聯狀態下誤以為出牌成功。
- 優先使用使用者點開的邀請 URL，避免其他房號的本地房主備份錯誤覆蓋新邀請。
- 房主斷開 PeerJS 訊號時嘗試重新註冊／恢復，失敗時給可見的操作資訊；房主切離遊戲仍可能造成連線中斷。
- 重要限制：WebRTC 在部分 5G／企業網路／對稱 NAT 環境無法直接建立候選連線，此時需要 TURN relay 才能保證高成功率；此版沒有部署 TURN，不能宣稱任何外網都 100% 可直連。參考 PeerJS FAQ。
- 獨立 Repository `YiQ1796/BigTwo_Web`，安全回退分支 `safe-rollback-v054-before-reconnect-20261031`，所有既有牌型、52 張猴子牌與 AI 功能保持不變。

## V0.5.6｜加密 WSS 備援與手機 5G 連線修復（2026-10-31）
- 對照《財富帝國》已使用的 MQTT over Secure WebSockets 設計理念，但完全獨立實作，不修改其他遊戲專案。
- 房主同時啟動 PeerJS P2P 與 WSS 訊息中繼；玩家優先透過 WSS 加入，若兩個中繼都不可用才回退到 P2P。
- 使用 EMQX、Mosquitto 的公開**測試** Broker，傳輸前透過 WebCrypto ECDH P-256 協商、AES-256-GCM 加密；每位玩家各有臨時金鑰／隔離通道，公開 Broker 不會收到明文手牌與玩家身分 token。
- **安全限制：公開 Broker 不具備服務保證，也未提供強驗證的端對端對方身分**，仍有主動中間人攻擊、惡意干擾與服務不可用的風險。**不得處理敏感個資、付款或正式商業使用**。真正正式營運應改用受控且帶 ACL 的私有中繼服務，並實作房主身分驗證。
- 保留原六位數字房號、12 種嘲諷、AI 補位、52 張猴子撲克牌、牌型規則及牌桌統計。
- 此版 GitHub Actions 驗證的是模擬端對端中繼；真實 iPhone 5G／公司網路仍需玩家實機驗收。安全回退：`safe-rollback-v055-before-wss-20261031`。
